从现象到研究.方案与研究练习

看不见数据，
也能算出结果？

把数据交给云计算，要不要先解密？全同态加密的一种用法是让云端处理密文，把计算结果也以密文发回，最后由持有密钥的一方解密。

先把角色分清

数据持有方

编码并加密输入，保管解密密钥。只交出密文和方案所需的公开参数、求值材料。

计算方

按约定电路对密文执行加法和乘法等操作。求值过程无需获得解密密钥。

结果接收方

由具备解密权限的一方解开返回密文。结果应与按明文执行同一计算相符，近似方案则允许受控误差。

例如，两条健康记录分别用一位表示是否符合某条件。用密文乘法可判断两条记录是否都满足条件。实际统计通常需要较大的明文空间才能表示人数。这个实验只使用一位，明文加法按模 2 计算。

手算一下，为什么能在密文上加和乘？

样例取奇数 p = 7919，密文 c = p × q + 2r + m，m 是 0 或 1。客户端除掉 p 的倍数，得到最靠近 0 的余量，再取其奇偶性。两份密文相加或相乘时，含 p 的项仍是 p 的倍数。余量里能影响奇偶性的只有明文组合，前提是余量没有因超出范围而折返。

取 A = 1、B = 0、r = 1，两份余量是 3 和 2。相加得 5，奇偶性给出 1。相乘得 6，奇偶性给出 0。把相加结果连续平方会得到 25、625；当 r = 2 时，相加得 9，平方两次得 6561，中心余量变成 −1358。因为减掉一个奇数 p，解密位从预期的 1 变成 0。

从有限深度到全同态

对单个比特，模 2 加法是异或，乘法是与。与常量 1 异或还能实现取反。把这些门连成电路，就能表示有限输入上的任意布尔计算。接下来要解决的是怎样让足够深的电路仍能正确解密。

部分同态

只支持某一类明文运算，例如加法，已经能完成一些加密汇总任务。

分层全同态

允许组合操作，按预先选择的乘法深度配置参数。乘法深度是任一输入到输出路径上串联的乘法层数，许多并行乘法不等于许多层。

全同态与自举

自举的一种经典思路是同态执行解密电路，把要解的旧密文变成加密同一明文的新密文，恢复后续计算能力。这个过程通常比一次加法更昂贵。

本页显示的是小整数例子的余量折返。真实格密码方案用不同的数学结构处理噪声、模数和参数。CKKS 还需管理数值尺度及近似误差。

云看不到明文之后，还要防什么？

结果推断

授权用户拿到细粒度汇总，仍可能从结果推测个体信息。限制过小分组、控制查询与发布频率，必要时为统计结果另行设计隐私机制。

错误或被改写的计算结果

现有演示允许求值方对密文做数学运算。实际系统需要明确能否信任执行方，对高价值任务可用业务复核或可验证计算来检查求值是否符合约定。

解密与密钥暴露

解密服务仍接触密钥和结果，应限制可解密的数据与主体，隔离密钥并记录调用。输出的可见范围和保留时间也要纳入设计。

元数据与成本

访问频率、消息大小和处理时序可能仍可见，昂贵的请求也会占用计算资源。按威胁模型单独处理元数据，并设置请求预算和异常监测。

回到密码学发展脉络

从方案选择走到科研问题

  • BFV / BGV：适合需要精确的模整数运算，如计数与汇总。先给输出范围设界，检查模回绕。
  • CKKS：适合允许近似实数或复数运算的任务，如矩阵计算和多项式推理。将解密结果与浮点基线比较。
  • TFHE 系列：常从布尔门或小整数的可编程自举出发，可用于比较等非线性操作。需测量单次操作与整体电路成本。

可复现练习

用公开合成数据和维护良好的库测试一个加密汇总，记录参数安全等级、密文大小、计算时间和输出误差。固定参数并比较两种计算相同乘积的电路，串行相乘与平衡树相乘。再比较明文和密文基线，分开报告加解密与求值耗时。
