这里的 TTL 和 IP 包的 TTL 一样吗？

DNS TTL 以秒表示记录还可缓存多久。IP 包的 TTL 在路由转发中递减，用来限制包能走多远。本例的两台解析器以 120 秒 TTL 缓存了旧地址，A 在切换前 90 秒取得旧记录，B 在切换前 30 秒取得。客户端只展示解析器的回答，自身缓存省略。

加密 DNS 和 DNSSEC 各解决什么？

DoH 用 HTTPS 保护客户端到所选解析器的通信。DNSSEC 验证签名数据的来源与完整性。签名区的坏签名与区域调度给出不同但合法的记录，需要不同的观测来区分。

HTTPS 是在哪儿解密的？

这所校园的站点让 CDN 终止浏览器的 TLS，再用另一条 HTTPS 连接访问源站。试着站到不同位置，看同一条线路上的数据形态。观察范围限定在首段连线、CDN 节点和源站应用。

看得到 IP、读得到内容、信得过网站，有什么区别？

在本例的直接 IP 连接上，中间链路能观察 IP、传输大小和时序。解密发生在对应 TLS 端点。浏览器核验证书链及域名是否匹配访问目标，站点业务是否值得信任仍要结合用户想访问的域名及其他信息。CDN 到源站的连接另行验证。

设备能互通，就应该允许互访吗？

怎样验证边界真的生效？

设计一张访问预期表，事先写下每个身份在每个网络位置下应看到的拒绝阶段。用受控环境对照 DNS 记录、TLS 端点、网络策略日志和应用审计记录。分别统计允许与拒绝两类案例，避免只验证一次成功请求。
