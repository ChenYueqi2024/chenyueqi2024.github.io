打开一个网页，数据会经过哪里？

笔记本通过校园网访问一个示例站点。接入点或交换机在局域网里转发帧，路由器把包送出子网，运营商网络继续转发，站点可能由 CDN、反向代理或源站中的某个节点应答。DNS 解析器帮助查找站点地址，随后的网页数据通常沿另一条逻辑路径送往站点。

  1. 浏览器终端上的客户端
  2. 接入点 / 交换机Wi-Fi / 以太网
  3. 默认网关连接不同子网
  4. 运营商 / 互联网多个独立管理的网络
  5. 站点入口CDN、反向代理或源站

下方用一台刚接入网络的设备和一个新建连接演示。已有网络设置、缓存和连接都可以复用。IP 转发贯穿多次消息交换，路径与回程也可能不同。

    以太网 / Wi-Fi

    接入本地链路

    铜线、光纤和无线电波可作为传输媒介，网卡负责接入相应的链路。以太网交换机根据 MAC 地址转发局域网里的帧，无线终端先与接入点关联，受保护的无线网络还会建立相应的链路安全状态。

    DHCPv4 / IPv6 路由器通告与 SLAAC / DHCPv6

    知道自己的地址与出口

    IPv4 终端常用 DHCPv4 获取地址、子网掩码、默认网关与 DNS 解析器。IPv6 的默认路由来自路由器通告，地址可由 SLAAC 或 DHCPv6 等方式获得。在常见配置中，终端根据本地路由表和前缀判断目标能否直接交付，访问异地目标通常先交给默认网关。

    DNS · A / AAAA

    把站点名称解析成地址

    本机没有有效缓存时，向递归解析器查询。解析器也会先查自己的缓存，必要时沿根、顶级域和权威服务器的委派查询。A 记录给出 IPv4 地址，AAAA 记录给出 IPv6 地址。

    ARP / IPv6 邻居发现 · IP / ICMP

    决定下一个包交给谁

    发往异地站点时，终端查的是本地网关的链路层地址。IPv4 常用 ARP，IPv6 用邻居发现。路由器按目的 IP 查转发表，通常选择最具体的匹配前缀，再经下一段链路发送。ICMP 可报告某些转发问题，也用于诊断。

    TCP · 源端口与目的端口

    让应用能在两端交换数据

    TCP 通常用 SYN、SYN-ACK、ACK 建连，之后提供可靠、有序的字节流。序号、确认与重传处理丢失，流量控制保护接收方，拥塞控制调节发送速率。

    TLS 1.3 · 在 TCP 连接之上

    核对对端身份并建立加密保护

    浏览器核对证书链、站点名等条件，通过 TLS 握手建立保护应用数据的密钥。TLS 通常保护浏览器到站点入口这一段。反向代理到源站的连接需要单独考虑。

    HTTP/2 · 在 TLS 和 TCP 之上

    把请求交给网站应用

    浏览器发送路径、方法与首部，站点返回状态、首部和正文。HTTP/2 可在同一个连接上交错传输多个流。收到 HTML 后，浏览器常按需再取图片、脚本和样式表。

    协议速查：各管哪件事？

    分层描述的是职责，请求步骤描述的是时间顺序。DNS 属于应用层，也需要底层先把查询送出去。下表以 TCP/IP 分层为主，并单列物理介质、主机配置和安全会话。OSI 的七层模型可用来讨论通信职责，两种模型的层次没有严格的一一对应关系。

    职责设备与协议什么时候参与
    传输比特网卡、双绞线、光纤、无线电每一段物理链路都要把比特变成可传输的信号。
    本链路交付交换机、接入点、以太网、Wi-Fi、MAC、VLAN每段链路各自成帧。VLAN 可划分逻辑局域网，跨网段流量由路由转发。
    配置与找邻居DHCPv4、IPv6 RA / SLAAC / DHCPv6、ARP / NDP设备接入、更新地址或寻找本链路下一跳时。DHCP 是提供配置的服务，ARP 和 IPv6 NDP 用不同机制找邻居。
    跨网段转发路由器、IPv4 / IPv6、ICMP、OSPF / BGP路由器逐跳转发 IP 包。OSPF 常在同一管理域内计算路由，BGP 在自治系统间通告前缀。它们维护可达性，网页请求不会为每个包重新跑一遍 BGP。
    进程间通信TCP、UDP、QUIC、端口端口区分服务和连接端点。UDP 提供数据报。TCP 提供有序字节流。QUIC 在 UDP 之上实现可靠流、拥塞控制和安全握手。
    身份与保密TLS、证书、证书颁发机构HTTPS 的身份验证与密钥协商发生在连接建立过程中。HTTP/2 走 TLS over TCP 时 TCP 先建连，QUIC 将 TLS 握手整合进连接建立。
    应用语义DNS、HTTP、SSH、SMTPDNS 查名字，HTTP 传网页或 API 数据，SSH 用于远程会话，SMTP 用于邮件传输。每种应用协议按自身规则使用底层传输。
    网络为什么把信息拆成包？

    互联网采用分组交换。来自不同应用的包可以在同一链路上交错发送，路由器按包决定下一跳。拥塞时，包会排队或被丢弃，端到端协议负责处理需要恢复的数据。浏览网页是客户端与服务端模式。在点对点应用中，同一个节点也可以同时请求和提供数据，底层仍然使用网络协议传输。

    带宽、时延、丢包分别影响什么？

    带宽是链路单位时间可传的比特量，吞吐量是实际传到的速率。时延包含传输、传播、处理和排队时间，RTT 是往返所需时间。丢包可能来自拥塞、干扰等，重传通常增加等待。请求的首字节慢，也可能是 DNS、握手或服务器处理慢。

    防火墙、负载均衡和 CDN 放在哪里？

    防火墙按策略控制允许通过的流量，可以部署在主机、网络边界或服务入口。负载均衡把流量分给多个后端，可按连接或按应用请求处理。CDN 把内容和服务放到多个边缘节点，常在靠近用户的位置应答。三者可能由同一设备或服务承担。

    风险落在哪一段，谁负责防？

    按最先被破坏的信任边界归类。一次事件可能波及多段，比如路由异常可以表现为握手超时，钓鱼页面也可能持有自己域名的有效证书。

    阶段风险与影响观察线索主要防护
    接入链路仿冒接入点、无线干扰。终端可能接错网，或根本无法保持连接。无线认证异常、频繁重连、接入点记录变化。受管网络配置、企业 Wi-Fi 验证认证服务器证书、监测无线环境。
    配置与找邻居非授权 DHCP、ARP 欺骗或伪造 IPv6 通告。终端可能得到错误设置或把帧交给错误的下一跳。网关或解析器突然改变，同一 IP 对应的链路地址异常变动。受管交换机上的 DHCP Snooping、动态 ARP 检查与 IPv6 RA Guard，辅以网络分段。
    名字解析DNS 缓存投毒、解析器配置被篡改。正确域名可能得到错误地址。解析器配置漂移、DNSSEC 验证异常，与可信观测的答案不一致。可信解析器、对已签名区域做 DNSSEC 验证。DoH 或 DoT 保护到所用解析器的传输。
    跨网转发IP 源地址伪造、BGP 路由劫持或泄漏。可出现错误来源标识、绕路或不可达。前缀的起源自治系统或传播路径异常，部分网络先受影响。入口源地址验证、前缀策略与 RPKI 起源验证。起源验证只核对起源授权，完整路径需另行评估。
    连接与可用性SYN 洪泛、反射放大或高流量 DDoS。连接状态、链路容量或服务资源被耗尽。握手完成率下降、入站流量或连接表飙升。应用层洪泛也可表现为后端排队。按瓶颈使用连接保护、限速、上游清洗和分布式承载。只在主机限速无法补回已被占满的上游链路。
    加密与身份中间人、明文降级、错误的证书信任配置。内容或对端身份可能失去保护。证书名不匹配、信任链报错或协议与预期不同。正常校验证书链与站点名，使用 HTTPS 和 HSTS，审计设备信任配置。
    网站与业务钓鱼、凭据滥用、越权、SQL 注入或 XSS。影响发生在用户决策、会话、服务端处理或浏览器渲染。登录风险提示、异常授权记录、请求与数据访问日志不一致。核对站点身份，采用抗钓鱼认证。服务端逐请求授权、参数化查询、上下文相关的输出编码。

    这些线索用来缩小范围。DNS 轮询、网关冗余、CDN 调度、证书更新都可能造成正常变化，结合多处记录才能判断原因。

    延迟究竟花在哪？

    用自己控制的站点，记录浏览器网络面板中的 DNS、连接、TLS 与等待首字节时间。固定浏览器、网络环境和资源，分别重复冷连接与连接复用条件，记录实际协商的 HTTP 版本与中位数。复用连接时，某些耗时栏可能没有独立记录。进一步比较同一站点的 HTTP/2 与 HTTP/3 时，同时记录 RTT、丢包与是否回退，避免把 CDN 或缓存的差异算入协议收益。
